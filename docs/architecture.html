Architecture

The repository separates gallery concerns, shared studio behavior, and individual card markup so designers can explore quickly without sacrificing maintainability.

Top-level architecture

card-collection/
├── assets/
│   ├── main.css
│   ├── main.js
│   └── card-lab.js
├── cards/
│   └── 15 independent demos
├── docs/
├── scripts/
└── .github/

Shared runtime

assets/card-lab.js owns design presets, CSS variable application, flip state, tilt interpolation, import and export, local preset persistence, keyboard behavior, and configuration methods.

Individual demos

Each demo owns its semantic content and any domain-specific visual structure. This prevents one giant conditional component from becoming the only way to understand or reuse the project.

Why vanilla JavaScript

There is no framework requirement because the project is intended as transferable source material. A React, Vue, Svelte, EJS, or server-rendered project can adopt the markup and tokens without first removing a framework abstraction.
